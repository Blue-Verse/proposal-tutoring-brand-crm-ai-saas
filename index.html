  • AI 리포트 멀티모델 어댑터 — 수업/주간/월간/심화 리포트 자동 생성, 등급별 모델 교체·폴백, 발송 전 관리자 승인
  • 자동화 — 상담 접수 알림·수업 리마인더·후기 요청·학생 화면(Notion) 자동 갱신
  • 결제 — 결제선생 청구 문자(링크), 미납 관리, 매출 집계, PG사 확장 대비 어댑터

  • 비기능 — 모바일 우선 반응형, Lighthouse 성능·접근성·SEO·모범사례 각 90점 이상, 노코드 빌더 미사용

  • 마일스톤 1(8/14) 엄수 우선 설계 — 공개 사이트(6페이지+약관)를 독립 배포 단위로 분리, 초기 스프린트에 집중해 지원사업 보고 일정 확보
  • 멀티테넌트 우선 아키텍처 — tenant_id + Supabase RLS 정책을 1일차부터 확정, 향후 다중 선생님 확장 시 재설계 없이 대응
  • AI 멀티모델 어댑터 실경험 — Claude·Gemini 등 다중 모델을 어댑터로 추상화하고 등급별 교체·폴백·품질 게이트를 운영한 경험 보유 → 요구된 REPORT_AI_LESSON/WEEKLY/MONTHLY/DEEP 환경변수 기반 구조에 그대로 적용
  • 승인 후 발송 워크플로우 — AI 결과 '참고용' 표기 + 관리자(선생님) 승인 후에만 발송되는 검수·승인 파이프라인 설계 경험(리포트 자동생성·승인 발송)
  • 관리 시스템·대상자 관리 경험 — 멀티테넌트 케어 관리, 어드민 대시보드, 알림 폴백 구조 다수 상용화 (학생 관리·학부모 알림과 직결)
  • Lighthouse 90+ 성능 최적화 — Next.js App Router 서버 컴포넌트·이미지 최적화·SEO 메타 설계로 4개 항목 90점 목표 달성

  • [필수] 알림 — Solapi 카카오 알림톡 우선, 실패 시 SMS 자동 대체
  • [필수] 자동화 — 상담 접수 알림·수업 리마인더·후기 요청, 학생 화면(Notion) 자동 갱신

3.3 AI 리포트 (멀티모델 어댑터)

  • [필수] 수업/주간/월간/심화 리포트 자동 생성 (4단)
  • [필수] 어댑터 패턴 — 유형별 환경변수(REPORT_AI_LESSON / WEEKLY / MONTHLY / DEEP)로 모델 지정, 실패 시 폴백
  • [필수] 모든 AI 결과 '참고용' 표기 + 관리자(선생님) 승인 후에만 발송
  • [필수] Notion API 연동 — 1차 학생·학부모 조회 화면 대체

4. 비기능 요구사항

5. 기술 제약사항

  • Next.js 15 (App Router), TypeScript, Supabase (PostgreSQL), Vercel 스택 준수
  • 외부 연동: 결제선생(청구 문자, PG 어댑터), Solapi(알림톡+SMS), Notion API, AI 멀티모델 어댑터
  • 도메인·서버(Vercel·Supabase)는 발주처 명의, 개발자는 협업자로 초대
  • AI·알림·결제 키는 발주처 발급, 서버 전용 / NDA 별도 체결, 저작재산권 발주처 귀속·저작인격권 불행사 특약
  • 재하도급 사전 서면 동의 필수, 라이선스 확인된 자산만 사용 / 상세 기능 명세서는 선정 후 별도 제공

  • 학생·학부모 자체 포털(1차는 Notion API 연동으로 대체, 자체 포털은 향후 단계)
  • 네이티브 모바일 앱(iOS/Android) — 모바일 우선 반응형 웹으로 대응
  • 외부 유료 API·AI 모델 사용료 및 서버/호스팅 비용
  • 1차 범위 외 신규 대규모 기능 (2차/유지보수 단계에서 협의)
